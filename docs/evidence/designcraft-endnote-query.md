# Original selected Endnote browser candidate

This experiment wires the original hosted Quick Apply `endnote.edit` action to a separate bounded `endnote.list` transport and the original generic Edit Endnote form. It preserves the original command registry, widgets, generated Endnotes listing, owned native processing and mutation ACK/FIFO. There is no replacement editor or new results pane.

The first real browser attempt exposed an existing hosted input gap: dragging only forwarded `text.placeCaret`, leaving a caret rather than the required complete reference range. The resolver was kept strict. A separately staged input candidate forwards the original Type Tool's Shift+Left/Right `text.move` command to the original native visual/UTF-8 algorithm. The QA gateway accepts exactly the four original fields, left/right, extend=true, word=false and far=false; six broader or malformed operations must refuse before mutation. Drag and broader navigation remain outside this candidate.

`BROWSER.json` pins the cumulative base, four-file UI overlay, both existing service modules, transport, and separate gateway/native input patch. The builders stage only reviewed source, refuse stale output and restore the exact source in `finally`. The input gateway is copied outside the repository; official gateway/native files and installed UI registration stay unchanged. Candidate assets have their own manifest and are served only under a local QA prefix. They are never labeled as the existing shipped patch or installed package.

A real pending-query browser run also exposed retained Quick Apply search focus: a new Ctrl+Enter could not open another palette during the async interval. After successful query capture, the shell now surrenders only the closed palette search focus. It does not do this on rejected capture, cancellation or late delivery, so a newer dialog/palette keeps its focus. The final test uses the original shortcut directly, without menu-click workarounds.

The query uses a fresh shell UUID and checked serial, actual session, current canonical context, fixed 10,000 ms monotonic deadline, exact AbortController cancellation and an 8 MiB streamed UTF-8 reply budget. Only a matching ticket and fully validated same-version native result can open the original form. Query errors do not enter the mutation error/FIFO handler; explicit retry is required after failure, cancellation or timeout.

Validation is provided by `scripts/smoke-designcraft-endnote-query-browser.mjs`, with generated native geometry used solely to position the real pointer. The editor receives no injected selection, offsets, story IDs or targets. The original pointer caret plus Shift+Arrow obtains its acknowledged range from the owned engine. The browser then uses the original Quick Apply, fields, confirmation, Undo and Redo.

The final complete run passes **30 browser assertions /13 unique original UI queries**, with **25 native /44 candidate gateway /189 UI tests (1 existing ignored) /102 repository tests**. Original pointer/Shift+Arrow, both story targets sharing id1, original Quick Apply/form, held/failed/forged reply, exact Escape cancellation, explicit retry, newer palette/range, newer held mutation and FIFO Q/R, fixed deadline, held original edit ACK, Undo/Redo, changed native listing pixels, retained Save Copy and fresh reopen all pass. One deliberate503 and AbortController cleanup/cancellation are expected; there are no unexpected browser errors. Four screenshots were inspected. Source is restored and QA closed.
