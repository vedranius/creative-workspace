# DesignCraft Go to Footnote Reference — alpha.72 candidate

The original Type > Go to Footnote Reference menu sends the unchanged `footnote.goToReference` command to the owned worker. The original engine resolves the note anchor and places the caret immediately after its UTF-8 reference. This is a selection-only, non-Undo command: document content, native saved-document identity, dirty/name state and existing Undo/Redo history remain unchanged. The UI retains its acknowledged note selection and page until the matching canonical ACK; pending body typing is held in the existing bounded FIFO and reaches the body only after that ACK.

The gateway and native entrypoint accept exactly an empty object. Unknown keys, paths and other parameter shapes are refused. The worker executes the original command first on an isolated selection candidate, then locates the visible body caret through the original composer across at most 64 pages before changing the real selection. Invalid note selection or an invisible reference is rejected before real mutation. The returned native page directs the acknowledged server render; it is not inferred from the currently displayed page. Existing root/session/Origin/auth, command queue, canonical, resource and provider boundaries remain intact. This bounded candidate check is not a complete memory guarantee.

The cumulative original-source patch adds the host allowlist, matching ACK path and clipped original menu hit-rectangle evidence; it does not replace the menu or reimplement reference/composition algorithms. The note address remains losslessly tagged on the wire. Failed or wrong ACKs retain note selection, and duplicate pending command submission is refused. Source pin remains `a127c6d5c3576972bbd60445f26d893db071eef3`; engine pins remain independent from the product version.
