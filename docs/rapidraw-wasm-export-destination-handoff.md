# RWASM-03 export destination host foundation — 2026-10-22

This completes the previously interrupted **host foundation**, not original ExportPanel or provider acceptance. `createExportBridge` accepts the pinned source single-file JPEG argument shape, calls the dedicated full RAW worker, binds output capabilities to File identity/document path/generation and publishes native-shaped progress/success only after destination close/readback ACK. It does not mutate the editor's clean/dirty state. The original React components, native source, Rust/WASM, preview/export budgets, public demo and A checkout are unchanged. No product version/release/public editor claim for this unintegrated experiment.

## New behavior and evidence

`createExportDestination` defaults to browser `showSaveFilePicker` and requires a separately selected retention (`until-ack` or `keep`). Only a new empty JPEG destination is admitted, with explicit granted read/write capability. It refuses a source filename/nonempty output, expired/foreign/single-use token and concurrent/unsettled prior I/O. At most16 choices remain for5min. The native-shape bridge rejects unsupported metadata/folder/mask/border/pad/watermark options and unbounded arguments/RAW before worker invocation; original codec preflight remains in the worker. File read has a30s logical timeout/abort; late read results cannot start a worker. Cancellation is immediate at this host API; bypassing the existing React preview queue remains the next integration task.

Before destination I/O, the JPEG is written/closed/read back in OPFS, hash checked and journaled `uncertain`. Permission plus empty-file size/lastModified are checked before opening the exclusive stream, before writing and before close. No automatic replay occurs. Output close **and** matching readback precede the `acknowledged` receipt. The current generation is rechecked, including after synchronous progress subscribers; only then can `export-complete` fire. `complete(receipt)` subsequently marks/reclaims the journal according to retention. Cleanup failure leaves the complete record and a cleanup-pending flag; it cannot turn a true ACK into a false save error. A failed/stale host does not accept the receipt or delete its recovery.

A shared30s deadline bounds each destination/journal transaction, not30s per individual call. Unresolved late operations prevent new writes. A stream created after timeout is aborted. Deadline/cancel do not guarantee physical browser I/O cancellation; close can still settle later, so uncertain bytes are retained. Storage quota/journal failure prevents destination writes and explicitly does not claim durable recovery. Inventory/read are bounded and validate retained bytes/hash. There is no recovery replay/delete UI yet.

Each has no success and retains exact JPEG recovery; newer destination content is unchanged and its stream is never opened. The picker is injected, not an OS permission acceptance claim.
- A second actual RAW worker cancels at `gpu-submitted`: owned device destruction ACK, no forced termination, no destination open, native-shaped cancelling/cancelled events. No browser/page/failed/external-request errors.
