The acknowledged quality95 JPEG remains successful, with a separate preference warning. No last-used write occurs, the host is still saving without uncertainty, and releasing the pending preset ACK preserves that preset and last-used60 at revision4. No automatic retry is scheduled.
- After reload, a genuine second browser page creates its own settings host/IndexedDB connection and commits an additional preset at revision5 while the first page holds output close. The stale first host still expects revision4. Its last-used save is refused by atomic revision CAS after file Success. The JPEG remains valid, the source host becomes uncertain, and the newer revision5/preset survives. Reload reconciles all presets without restoring a RAW document, file handle, chooser grant or destination path.
