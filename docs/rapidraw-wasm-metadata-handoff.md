# RWASM-03 — original Exposure metadata auto-save/read ACK (2026-10-24)

The original Basic Exposure control, `useImageProcessing` debounce, `debouncedSave`, `load_metadata` and `useImageLoader` now round-trip the supported Exposure slice through private browser storage. The native-shaped `save_metadata_and_update_thumbnail` Promise resolves only after one atomic IndexedDB commit and exact readback. Its source `thumbnail-generated` listener receives the new thumbnail only after that ACK. [Browser proof](evidence/rapidraw-wasm/metadata-browser.json) · [Editor screenshot](evidence/rapidraw-wasm/metadata-browser.png) · [Uncertain-write error](evidence/rapidraw-wasm/metadata-browser.uncertain.png).

All original React hooks, store, controls, normalizer, command IDs and algorithms remain unchanged at RapidRAW `b39884b38d8f148caef6fd0d52afd264951be329`. Eight additional metadata contracts are pinned in `UPSTREAM.json`, alongside the existing17 UI hashes. The isolated `metadata` composition opts into the backend and observes the original store to compare its current draft with the acknowledged Exposure. The original store has no saved/dirty field or success indicator: the reported dirty state belongs to this experimental host, not a newly invented product indicator. Source auto-save failure still uses the original toast. Existing proof variants opt out and preserve their prior behavior.

A record is bound to SHA256 of the complete user-selected File bytes and its byte length. Filename, modification time, opaque session path and file authority do not persist. Re-selecting renamed identical bytes restores the edit; different bytes with identical names/size/time have distinct identities. Originals are read-only. `load_image` reuses the exact acknowledged early-load snapshot; it cannot silently advance the CAS revision while the editor still displays an older metadata baseline. A focused regression test protects that interleaving.

Storage is separate from JPEG settings, development-preset CRUD and output recovery: `cw-rapidraw-metadata-v1` / `metadata` / `documents`. One bounded record holds schema, global revision and up to32 content identities, each with Exposure and a local JPEG thumbnail. Exposure is finite−5..5; all other adjustment values must equal the original normalized defaults. Input adjustments are capped at64KiB, renderer thumbnail bytes at90KiB, encoded thumbnail at128KiB and the complete stored record at4MiB. File reads retain the existing RAW input limit; IO has a10s deadline. These are encoded/input bounds, not peak or aggregate-memory guarantees, and browser quota/eviction remains possible. There is no automatic deletion or eviction of older metadata to make room.

The transaction compares the previously read global revision before replacing the record. A stale writer preserves the other tab's result. Commit abort, deadline, readback mismatch or corruption keeps uncertainty visible and refuses further saves until an explicit settled reload. Dirty state compares the latest draft with the acknowledged value, so ACK for an older edit cannot clean a newer draft. Readback failure preserves a durable record without claiming success; reload reads it with zero replay commits. Unsupported effects, flags/geometry/other tools and unknown fields refuse before persistence. No XMP/sidecar, EXIF, filesystem metadata write or backend-directory compatibility is implemented or claimed.

For this local cache, the bridge reuses the already pinned original400px/q80/clipping-off preset-preview algorithm. It atomically stores that real JPEG with Exposure and emits the original listener's supported `data` payload after ACK. The full native sidecar command instead resolves lens parameters, writes filesystem metadata and queues its configurable thumbnail work asynchronously; its source is traced, not claimed identical to this browser backend. No new native metadata-filesystem parity claim is made.
