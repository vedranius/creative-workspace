# RWASM-03 — last-used export preference acknowledgement

This isolated experimental native-source WASM change is on `codex/rapidraw-wasm-port`. It adds no product release, main integration or public demo. Only the public hash-pinned CC0 Canon A410 DNG is used; private photographs remain untouched. [Browser evidence](evidence/rapidraw-wasm/last-used-settings-browser.json) · [Inspected screenshot](evidence/rapidraw-wasm/last-used-settings-browser.png).

The original ExportPanel saved `__last_used__` before starting export, did not await its settings callback, and skipped the save when a browser output capability contained no directory separator. Native `export_images_impl` launches a background job and returns before completion; moving the save directly after `invoke` would still be premature. The original `export-complete`/`export-error`/`export-cancelled` listeners update the process store. Both native export processing and the original listener are separately hash-pinned by the new patch metadata. Native behavior is source-traced, not newly exercised here.

The explicit [ExportPanel patch](../patches/rapidraw/b39884b3/export-last-used-ack-v1.patch) captures the actual exported settings and waits for the original terminal Success state. The browser bridge emits Success only after destination close and exact file readback ACK. It then awaits `onSettingsChange` separately, retains the previous settings store until IndexedDB commit/readback ACK, and catches preference errors without converting the already acknowledged file into a failed export. It merges the captured last-used values with the latest settings/preset list. A pending preference disables another export until it settles; failed preferences show “File saved. Last-used settings were not saved. Reload settings before trying again.” No path is added to the preset, and the bounded settings host still removes paths, grants, handles and chooser authority. Cancel/error clears the pending preference; no retry or output replay is introduced.

The prior two-file settings/list ACK patch remains unchanged. Only the settings QA variant applies the additional ExportPanel patch; the ordinary export proof variant retains the exact original source. Original command/event IDs, layout controls, export settings algorithms, image processing, native libraries and WASM are retained, with the new pending/error text explicitly acknowledged as a reviewed UI change. This does not claim an unchanged ExportPanel file or full App/native-platform acceptance.

Sandboxed Chromium uses actual original controls and real OPFS/IndexedDB transactions:

- Reload: original controls apply the stored values, but no RAW document or destination authority restores. A new explicit RAW and output choice is required.

- Inject output-close failure: target remains empty, source reports Error, no preference write occurs and the recovery JPEG remains uncertain. Cancel the chooser: no new output or preference write.
- Use the actual original Cancel handler at GPU submission: source becomes Cancelled, target remains empty, no preference commit occurs and the earlier failed-output recovery remains intact.
