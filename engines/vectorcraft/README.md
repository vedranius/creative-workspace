# Workspace-owned VectorCraft

The independent `cw-vectorcraft-engine` embeds [VectorCraft 0.8.0 by the ArtCraft team](https://github.com/storytold/vectorcraft), pinned by `manifest.json`. Our original Rust adapter and upstream libraries are MIT OR Apache-2.0; the surrounding Creative Workspace gateway/browser code is AGPL-3.0-only. The upstream source is unchanged. Its `Headless` backend supplies engine commands and CPU document rendering; no desktop transport or public MCP server is started. Upstream also has a WASM app, but it would process artwork on the laptop, so this integration uses the server engine and our own browser interface.

Install with `npm run engine:vectorcraft:install`. Rust 1.95+ and a native linker are required. `CW_VECTORCRAFT_RUNTIME`, `CW_VECTORCRAFT_SOURCE` and `CW_VECTORCRAFT_BINARY` select owned paths. The installer preserves upstream dependency versions in Cargo.lock, adding only our shim package, and retains upstream license/attribution notices. Fonts are not bundled by this prototype.

The browser prototype opens SVG and `.vectorcraft`/legacy `.drawcraft`, creates canvases, draws rectangles/ellipses/freehand paths/stars/polygons, selects objects from the bounded layer tree or approximate bounding-box hit testing, changes fill/stroke, moves/deletes objects and supports undo/redo. Previews and exports come from the native server engine. One document per session, four concurrent sessions, 64 MB input/export limit. A native `.vectorcraft` save preserves editable state and marks clean only after destination ACK; SVG/PDF/PNG exports alone do not mark unsaved artwork clean. SVG/PNG use the selected artboard (PNG up to 2048 px); PDF/native retain all artboards. New filenames only; originals cannot be overwritten. Exports requiring additional asset files are refused before publication rather than silently delivering an incomplete file.

Read and write roots are separate. The engine opens the selected server/on-demand file directly; dependencies it reads must stay inside the chosen source root. Native exports first go into a private session directory, then publish atomically to a new server filename or an exclusive laptop filename through common provider ACK/recovery. No full-library upload is required for on-demand mode. Relinking/package workflows and complex linked-asset fidelity are pending.

Validation: `npm run check`, `npm test`; `CW_VECTORCRAFT_BINARY=… CW_FUSE_BINARY=… node scripts/smoke-vectorcraft.mjs report.json`. The native Linux proof opens generated SVG, edits, renders, exports four formats, reopens native/SVG, keeps originals byte-identical and verifies independent native read/write roots. A generated WebSocket laptop agent plus real FUSE verifies selected-file reads, untouched unrelated data, laptop ACK/download/reopen and server output. Isolated Chromium tests verify upload, drawing, colour, movement, undo/redo, native save/download/reopen, mobile layout and the folder-mode dialog. Real directory-picker permissions are not automated; native Windows/macOS and full upstream tool parity remain unverified.
