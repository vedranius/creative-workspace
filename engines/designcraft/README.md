# Workspace-owned DesignCraft

Independent `cw-designcraft-engine` embeds [DesignCraft 0.5.0 by the ArtCraft team](https://github.com/storytold/designcraft), pinned in `manifest.json`. Our original Rust shim and upstream libraries are MIT OR Apache-2.0; surrounding gateway/browser code is AGPL-3.0-only. Upstream libraries are unchanged. Its native Headless backend composes and renders pages on the server; no desktop transport or public MCP server starts. The browser runs our own UI.

Install with `npm run engine:designcraft:install` (Rust 1.90+ and a native linker). `CW_DESIGNCRAFT_RUNTIME`, `CW_DESIGNCRAFT_SOURCE` and `CW_DESIGNCRAFT_BINARY` choose dedicated owned paths. The installer preserves upstream pinned dependencies, adding only the shim's workspace package to Cargo.lock, and retains license notices. The source includes bundled OFL document fonts such as Source Sans 3; optional craft-fonts and automatic external Document Fonts loading are not enabled by this adapter.

Prototype workflow: new 1–64 page publications; open/upload native `.designcraft`; page navigation; text/rectangle/ellipse frames via dimensions or pointer gestures; whole-story text editing, type size/family, native overset reporting, frame resize/reflow, fill swatches, select/move/delete/undo/redo. UI text drafts survive selection changes, prevent silent source changes, and are committed before Save. A native copy marks clean only after destination ACK; PDF (all pages) and PNG (current page, up to 2048 px) exports do not themselves mark unsaved work clean. New filenames only; originals are preserved.

Authority is deliberately narrower than upstream's CLI. Upstream `file.open` automatically loads adjacent fonts, linked images and data-merge sources without root confinement. Our shim instead reads the selected file through a canonical source-root check and uses the pure memory native-format importer, avoiding those automatic filesystem reads. Commands with arbitrary file paths are not forwarded. Outputs first go into an isolated private root, then publish through the common provider to server copies or exclusive laptop files with ACK/recovery. On-demand reads only the selected native package; pre-uploading the entire folder is unnecessary.

Limits: one document/session, four sessions, 64 MB input/expanded ZIP/export, 2,048 ZIP entries, 64 pages, 5,000 grouped items/16 levels, 1 MB total story text and a 20,000-character browser text editor (longer stories stay read-only). Embedded PNG/JPEG assets up to 16 MP are supported; linked-only assets and other embedded media are explicitly rejected. Full IDML, custom document fonts, data merge, linked-asset packaging, image placement controls, full upstream tool parity, autosave, stress and native Windows/macOS validation remain follow-ups.

Validation: `npm run check`, `npm test`; `CW_DESIGNCRAFT_BINARY=… CW_FUSE_BINARY=… node scripts/smoke-designcraft.mjs report.json`. Native Linux proof creates text/shapes, changes typography, detects/resolves overset, edits stories/moves/undo/redo, exports PDF/PNG/native and reopens native while preserving originals. A generated laptop agent with real Linux FUSE confirms selected-file reads, zero unrelated reads, acknowledged native output/download/reopen and separate server output. Two native Rust regression tests reject ZIP expansion over budget and external input paths. Scoped shim fmt/clippy pass. Isolated Chromium tests verify real controls, a counted native object from pointer drawing, draft preservation/save, resize/overset, PDF/native download/upload/reopen, three folder modes and mobile layout. Real user directory-picker permissions are not automated.
